# libgdx-ui-markup 0.6.0 Release Design

**Status:** Approved for implementation planning

**Date:** 2026-08-10

## Decision

Release the reusable markup-component language and structured diagnostic/provenance work merged
after `v0.5.0` as `libgdx-ui-markup 0.6.0`. This is a minor release because it adds public markup
syntax, public diagnostic model types and exception kinds, new parser bounds, and preview status
schema 3 while retaining the existing build and rendering contracts.

The release uses the repository's established two-PR workflow:

1. a reviewed release-candidate PR adds immutable `0.6.0` notes and the executable release plan;
2. the signed `v0.6.0` tag on that reviewed merge commit publishes Maven Central artifacts and
   anchors the GitHub release;
3. only after public artifact verification, a reviewed documentation PR changes current-version
   examples from `0.5.0` to `0.6.0`.

Directly tagging the current feature merge is rejected because it would omit reviewed release
notes. Publishing documentation coordinates before Maven Central resolves them is also rejected.

## Release scope

The release scope is exactly the first-parent change from `v0.5.0` through the reusable-component
merge on `main`. Release notes must cover:

- document-local parse-time components using bounded `<components>`, `<component>`, `<param>`,
  `<use>`, `<slot>`, and `<fill>` syntax;
- parameter defaults and requirements, required and fallback slots, nested composition, root
  overrides, and deterministic class merging;
- GL-free expansion into ordinary immutable elements before `MarkupBuilder`, so component-only
  nodes never cross the model-to-Scene2D boundary;
- structured source and invocation provenance through `MarkupSourceLocation`,
  `ElementProvenance`, `ComponentTraceFrame`, and `MarkupDiagnosticContext`;
- typed component diagnostics and deterministic nearest-name suggestions;
- preview `markup-status` schema 3 and corresponding IntelliJ presentation;
- transactional preview reload, harness transparency, the component-backed sign-in fixture, ADR,
  and executable cookbook updates;
- the final review remediation: 256-character XML/custom-tag names, at most 256 custom tags per
  parser, and explicitly bounded suggestion candidates;
- compatibility: component-free documents retain their concrete model and actor behavior, and
  preview, qualification, and IDEA artifacts remain unpublished.

The post-`v0.5.0` current-version documentation merge is included only where it describes current
behavior; it does not add extra published artifacts.

## Published artifacts

Publish exactly these Maven Central coordinates at version `0.6.0`:

- `io.github.teemuki8:libgdx-ui-markup:0.6.0`
- `io.github.teemuki8:libgdx-ui-markup-runtime:0.6.0`
- `io.github.teemuki8:libgdx-ui-markup-harness:0.6.0`

Do not publish `libgdx-ui-markup-preview`, `libgdx-ui-markup-qualification`, or
`libgdx-ui-markup-idea`. Java 25, libGDX 1.14.2, harness 1.2.0 / minimum 1.1.0, and agent-runtime
2.0.0 / minimum 1.0.0 remain unchanged.

## Candidate and review flow

The candidate branch is `agent/release-0.6.0`, forked from the clean synchronized `main` merge
commit `62af2084736d34e5277c8301d22b348b2561eb48`. It contains:

- this approved design;
- `docs/releases/v0.6.0.md`, used verbatim as the GitHub release notes;
- `docs/superpowers/plans/2026-08-10-release-0.6.0.md`, containing exact commands and acceptance
  criteria.

The candidate must pass the clean JDK 25/Xvfb release gate, independent exact-head review, and all
GitHub checks. The review handoff records the exact reviewed SHA independently of the mutable PR
and branch refs; every subsequent check and the merge guard must compare those refs with that
recorded value rather than rediscovering the candidate SHA. Immediately before merge, fetch and
require hosted `main` to remain exactly the reviewed candidate base. Merge the candidate PR only
with expected-head protection. After merge, capture the PR merge commit, require its first parent
to be the reviewed base and its second parent to be the recorded reviewed candidate head, and
require local `main`, `origin/main`, and GitHub to resolve to that captured commit. Any candidate
head change or intervening `main` advance stops this release candidate rather than silently
broadening its scope.

## Publication data flow

Create one annotated PGP-signed tag named `v0.6.0` with message
`libgdx-ui-markup 0.6.0`, signing explicitly with fingerprint
`2EB8F98C568F89038071930EF0484A483AB9CC7B`. Machine-check the `VALIDSIG` fingerprint and require
the tag's peeled commit to equal the captured reviewed candidate merge before pushing. Record the
annotated tag object's own object ID and require both that object ID and the peeled commit to match
the remote refs after push. Never move, replace, or reuse the tag.

Pushing the tag invokes `.github/workflows/release.yml`. The workflow owns all secret-bearing
operations and must:

1. verify the trusted tag-signing key, semantic tag, annotation, signature, and commit binding;
2. prove strict dependency locking and verification without write/bypass flags;
3. qualify minimum and current ecosystem profiles;
4. run clean checks and Javadocs and build the deterministic signed Central bundle;
5. upload exactly the three public modules;
6. require Central `VALIDATED`, request publication, and require Central `PUBLISHED`.

No credential, private key, passphrase, authorization header, deployment identifier, or temporary
curl configuration is copied into repository files, release notes, comments, or retained success
artifacts.

## Failure handling

- If the candidate gate, review, or hosted CI fails, fix the branch, rerun the affected and full
  gates, re-review the new exact head, and do not tag.
- If hosted `main` differs from the reviewed candidate base immediately before merge, or the merge
  commit's two parents are not the reviewed base and candidate head in that order, stop and prepare
  a newly scoped and reviewed candidate instead of tagging.
- If local tag signing or verification fails, leave the tag unpushed, diagnose the configured key,
  and do not substitute an unsigned or lightweight tag.
- If the tag push succeeds but the release workflow fails, do not move or recreate the tag. Repair
  only through an explicitly reviewed recovery compatible with the immutable tag.
- If Central is `PENDING`, `VALIDATING`, or `PUBLISHING`, keep monitoring. Those states are not
  completion.
- If Central reports `FAILED`, retain the workflow evidence and stop before creating a GitHub
  release or updating installation examples.
- If a public artifact is unavailable after workflow success, keep the release incomplete and poll
  the authoritative Central endpoints until every required file resolves or a real failure is
  identified.

## Public verification

After the release workflow reports success, independently fetch for each public module:

- the POM;
- the main JAR;
- the sources JAR;
- the Javadoc JAR;
- the detached `.asc` signature for each of those four files.

Every request must return HTTP success with a non-empty payload. Verify the remote annotated tag
object and peeled commit still match their locally verified values, with the peeled commit bound to
the reviewed merge, then create a non-draft latest GitHub release titled
`libgdx-ui-markup 0.6.0` from `docs/releases/v0.6.0.md` with tag verification enabled.

## Post-publication documentation

Only after public Central verification, create `agent/docs-0.6.0-current-version` from the
synchronized release `main`. Change current tested/published markup coordinates from `0.5.0` to
`0.6.0` in:

- `README.md`;
- `docs/guides/agentic-cookbook.md`;
- `docs/guides/embedding.md`.

Preserve historical release notes and the unchanged ecosystem dependency versions. Review and
merge this documentation PR with exact-head protection and hosted checks, then reconcile local
`main` again.

## Acceptance criteria

The release is complete only when all of the following are true:

1. the candidate notes accurately describe `v0.5.0..candidate` and contain no unreleased claims;
2. `xvfb-run -a ./gradlew clean check javadoc publishToMavenLocal --warning-mode=fail` succeeds;
3. the candidate PR has no unresolved actionable review findings and all required checks pass;
4. signed tag `v0.6.0` verifies with the required fingerprint, its local and remote annotated tag
   object IDs match, and it peels to the exact reviewed candidate merge commit;
5. the tag-triggered release workflow succeeds through Central state `PUBLISHED`;
6. all three module coordinates and all required artifacts/signatures resolve publicly;
7. the latest non-draft GitHub release targets immutable tag `v0.6.0` and uses committed notes;
8. the post-publication current-version PR passes review and CI and is merged;
9. local `main`, `origin/main`, and hosted `main` are equal and the worktree is clean.

## Non-goals

This release does not publish the preview, qualification runner, or IDEA plugin; change ecosystem
dependency versions; add another feature; alter the release workflow; regenerate dependency locks
or verification metadata; delete historical release branches/tags; or publish from an unreviewed
commit.
