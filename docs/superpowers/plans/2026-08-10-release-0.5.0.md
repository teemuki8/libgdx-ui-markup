# libgdx-ui-markup 0.5.0 Release Implementation Plan

> **For agentic workers:** Execute this plan task-by-task in one release-owner session. Do not
> move or reuse the tag, expose release secrets, or call the release complete before Maven
> Central reports `PUBLISHED` and the public artifacts resolve.

**Goal:** Publish the reviewed GDXCSS language expansion and agentic cookbook as
libgdx-ui-markup 0.5.0.

**Architecture:** One reviewed documentation commit becomes the immutable release candidate.
The repository's signed-tag GitHub Actions workflow builds and signs the three public Maven
modules, validates and publishes the Central deployment, and only then permits creation of the
GitHub release from the immutable tag.

**Tech Stack:** Git, GitHub pull requests and Actions, Gradle Wrapper, JDK 25, Xvfb, GnuPG,
Maven Central Portal.

## Global Constraints

- Release version: `0.5.0`; signed annotated tag: `v0.5.0`.
- Candidate branch: `agent/release-0.5.0`; base branch: `main`.
- Publish only `libgdx-ui-markup`, `libgdx-ui-markup-runtime`, and
  `libgdx-ui-markup-harness`.
- Keep preview, qualification, and IDEA plugin artifacts unpublished.
- Preserve strict dependency locking and verification; never use dependency bypass/write flags.
- Never expose Maven Central credentials, signing key material, or passphrases.
- Never move or reuse the release tag.

### Task 3: Sign, publish, and verify Maven Central

**Files:**
- Read: `.github/workflows/release.yml`
- Read: `release-public.asc`

**Interfaces:**
- Consumes: the reviewed `main` merge commit from Task 2 and release signing fingerprint
  `2EB8F98C568F89038071930EF0484A483AB9CC7B`.
- Produces: immutable signed tag `v0.5.0` and Maven Central publication of all three public
  modules.

- [ ] **Step 1: Create and verify the signed annotated tag**

Run:

```bash
git tag --sign v0.5.0 --message "libgdx-ui-markup 0.5.0"
git tag --verify v0.5.0
test "$(git rev-list -n 1 v0.5.0)" = "$(git rev-parse main)"
```

Expected: a good signature from the configured release key and exact candidate binding.

- [ ] **Step 2: Push the immutable tag and monitor publication**

Run:

```bash
git push origin v0.5.0
release_sha="$(git rev-parse 'v0.5.0^{}')"
runs="$(gh run list --repo teemuki8/libgdx-ui-markup --workflow Release \
  --event push --limit 20 --json databaseId,headSha)"
run_id="$(jq -r --arg sha "$release_sha" \
  'map(select(.headSha == $sha)) | first | .databaseId // empty' <<<"$runs")"
test -n "$run_id"
gh run watch "$run_id" --repo teemuki8/libgdx-ui-markup --exit-status
```

Expected: the `Release` workflow validates the tag, passes the strict release gate, uploads,
validates, publishes, and reports success.

- [ ] **Step 3: Verify every public Central artifact**

For each of `libgdx-ui-markup`, `libgdx-ui-markup-runtime`, and
`libgdx-ui-markup-harness`, fetch the `0.5.0` POM, main JAR, sources JAR, Javadoc JAR, and the
`.asc` signature for each artifact from Maven Central. Require HTTP success and non-empty
