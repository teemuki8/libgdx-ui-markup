# libgdx-ui-markup 0.6.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the reviewed reusable-component and structured-diagnostic work as
libgdx-ui-markup 0.6.0, verify Maven Central and GitHub state, and update current-version examples.

**Architecture:** A reviewed release-candidate PR contributes immutable notes and this runbook.
One signed annotated tag on the reviewed merge invokes the existing secret-bearing release
workflow, which publishes exactly three modules and waits for Maven Central `PUBLISHED`. A second
reviewed PR updates current-version examples only after public artifacts resolve.

**Tech Stack:** Git, GitHub pull requests and Actions, Gradle Wrapper 9.6.1, JDK 25, Xvfb,
GnuPG, Maven Central Portal, curl, jq.

## Global Constraints

- Release version is exactly `0.6.0`; the immutable signed annotated tag is exactly `v0.6.0`.
- Candidate branch is `agent/release-0.6.0`; its base is reviewed `main` commit
  `62af2084736d34e5277c8301d22b348b2561eb48`.
- Publish only `libgdx-ui-markup`, `libgdx-ui-markup-runtime`, and
  `libgdx-ui-markup-harness`.
- Do not publish preview, qualification, or IDEA plugin artifacts.
- Preserve Java 25, libGDX 1.14.2, harness current/minimum 1.2.0/1.1.0, and agent-runtime
  current/minimum 2.0.0/1.0.0.
- Preserve strict dependency locking and verification; never use dependency refresh/write or
  lenient/off verification flags.
- Never expose Maven Central credentials, signing key material, passphrases, authorization
  headers, or private administrative state.
- Never move, replace, or reuse `v0.6.0` after it is pushed.
- Do not create the GitHub release or update installation examples before Central reports
  `PUBLISHED` and every required public artifact resolves.

Create `docs/releases/v0.6.0.md` with this content:

````markdown
# libgdx-ui-markup 0.6.0

## Highlights

- Adds document-local reusable markup components with bounded `<components>`, `<component>`,
  `<param>`, `<use>`, `<slot>`, and `<fill>` syntax.
- Supports required and defaulted parameters, required and fallback slots, nested composition,
  root attribute overrides, and deterministic class merging.
- Expands components in the GL-free parse layer into ordinary immutable elements before
  `MarkupBuilder`; Scene2D actors and the harness never observe component-only nodes.
- Adds immutable source and invocation provenance through `MarkupSourceLocation`,
  `ElementProvenance`, `ComponentTraceFrame`, and `MarkupDiagnosticContext`.
- Adds typed component diagnostics, bounded deterministic nearest-name suggestions, and component
  trace presentation in the preview and IntelliJ plugin.
- Upgrades preview `markup-status` to schema 3 with bounded structured fields while retaining
  transactional last-good hot reload behavior.
- Updates the sign-in fixture, README, ADR, and executable agentic cookbook recipes to exercise
  components through parse, build, preview, harness, and IDEA integration paths.
- Hardens the parser trust boundary with 256-character XML/custom-tag names, at most 256 custom
  tags per parser, and explicitly bounded suggestion candidate work.

## Compatibility and scope

Component-free markup retains its existing concrete element and actor behavior. The existing
two-argument `MarkupDocument(Element, int)` constructor and its `root()` / `byteLength()` accessors
remain available; new source/provenance accessors are additive. Existing `MarkupException`
construction and location accessors remain available, with additive structured context and
component-specific kinds.

Consumers that parse the preview's `markup-status` line must accept schema version 3 and its new
structured diagnostic fields. The preview and IDEA plugin remain unpublished application/tooling
artifacts.

Component syntax is deliberately document-local and bounded. There is no component discovery,
file or URL import, dynamic tag construction, loop, conditional, arithmetic, script, reflection,
implicit ID namespace, runtime-state ownership, or arbitrary Java invocation.

Published modules require Java 25 and libGDX 1.14.2. The release gate qualifies harness 1.2.0 /
agent-runtime 2.0.0 and the minimum harness 1.1.0 / agent-runtime 1.0.0 profile. V1 remains scoped
to LWJGL3 desktop and Scene2D/Scene2D.UI.

## Published modules

- `io.github.teemuki8:libgdx-ui-markup:0.6.0`
- `io.github.teemuki8:libgdx-ui-markup-harness:0.6.0`
- `io.github.teemuki8:libgdx-ui-markup-runtime:0.6.0`

The preview, qualification runner, and IDEA plugin remain unpublished.
````

- [ ] **Step 1: Fetch every required Central artifact and signature**

Run in one shell:

```bash
set -euo pipefail
release_evidence="$(mktemp -d)"
central="https://repo.maven.apache.org/maven2/io/github/teemuki8"
for module in libgdx-ui-markup libgdx-ui-markup-runtime libgdx-ui-markup-harness; do
  base="$central/$module/0.6.0"
  for suffix in .pom .jar -sources.jar -javadoc.jar; do
    name="$module-0.6.0$suffix"
    curl --fail --silent --show-error --location --retry 90 --retry-delay 10 \
      --retry-all-errors --retry-max-time 900 --output "$release_evidence/$name" \
      "$base/$name"
    curl --fail --silent --show-error --location --retry 90 --retry-delay 10 \
      --retry-all-errors --retry-max-time 900 --output "$release_evidence/$name.asc" \
      "$base/$name.asc"
    test -s "$release_evidence/$name"
    test -s "$release_evidence/$name.asc"
  done
done
find "$release_evidence" -type f -printf '%f %s bytes\n' | sort
```

Expected: 24 non-empty files: four artifacts and four signatures for each of three modules.
